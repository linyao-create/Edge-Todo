# 一角 Windows 安装工作流

当用户在 Windows 电脑上说「帮我配置这个项目」时，立即按以下步骤执行。用户无需理解开发术语。执行过程使用用户可用的桌面、浏览器和飞书工具。仅在需要用户选择、登录、授权或系统确认时请用户操作。

## 1. 选择浏览器、检查环境并安装应用

- 先问用户要配置 Edge、Chrome，还是两个都配置。支持两个都选，也支持用户选择跳过扩展。检查本机是否已安装所选浏览器（Edge 默认位于系统 `Microsoft\Edge\Application\msedge.exe`，Chrome 默认位于 `Google\Chrome\Application\chrome.exe`）；缺少时给出官方安装入口（Edge：https://www.microsoft.com/edge ；Chrome：https://www.google.com/chrome/ ），同时继续其他已授权步骤。
- 检查本机是否已安装 .NET 10 SDK（运行 `dotnet --list-sdks` 确认包含 `10.0.`）。若未安装，可通过官方 `winget install --id Microsoft.DotNet.SDK.10` 或微软官方下载页引导安装。
- 项目目录记作 PROJECT，取实际绝对路径。默认数据目录为 PROJECT 的上一级目录下的「EdgeTodo数据」，与项目文件夹并列。若该目录已有数据，不覆盖、不删除、不初始化已有文件，先确认其归属并使用现有数据或另建独立目录。验收必须使用新建的隔离目录。保留实际绝对路径供后续使用和最终告知用户。
- 未配置的应用直接启动时会使用 `%LOCALAPPDATA%\EdgeTodo\`，这可能是旧版正在使用的数据。先只读检查旧版数据目录及注册表 `HKCU\Software\Classes\edgetodo\shell\open\command` 指向的可执行文件与运行中进程；不要直接启动未配置的应用，不要替换、清理、迁移或修改旧应用及数据。默认给新版使用独立数据目录；如目标目录已有内容，不得假定可以使用，先让用户选择确认或创建另一个新目录。若用户希望沿用或迁移旧记录，先解释将涉及旧数据，获得用户明确同意并完成备份后再操作。不要声称旧数据已自动迁移。
- 执行 `powershell -ExecutionPolicy Bypass -File .\windows\package-win.ps1 -OutputDir "<安装目录>"` 构建并发布 Windows 应用（包含 `EdgeTodo.exe` 与命令行工具 `EdgeTodoCmd.exe`）。
- 运行 `powershell -ExecutionPolicy Bypass -File .\windows\configure-data-dir.ps1 -AppDir "<安装目录>" -DataDir "<数据目录>"`，将数据目录写入该应用副本旁的 `edgetodo-config.json`。
  - 如正在进行并行隔离测试且本机已有正在使用的旧版，必须使用 `-ProtocolScheme "edgetodo-test" -SkipProtocolRegistration`（严禁覆盖原有 `edgetodo://` 浏览器收藏入口），并用独立的测试协议 URI（例如向测试副本直接传递 `edgetodo-test://capture?id=<uuid>&title=<title>&url=<url>`）验证测试目录收到收藏而旧版毫发无损；
  - 只有在全新的测试环境，或用户在实机测试前明确允许且先备份原始注册表、测完立刻精准还原的前提下，才可使用 `-RegisterProtocol -ForceRegisterProtocol` 让现有浏览器扩展将网页直接发送给该测试副本。
- 验证 `edgetodo-config.json` 与注册表协议指向后，正常启动应用。检查进程是否存在同名运行中的旧版，避免覆盖、替换或终止其他版本。验收时确认两个不同数据目录的实例可同时运行，且 CLI（`EdgeTodoCmd.exe --data-dir "<目录>" ...`）与协议请求各自写入对应目录、互不串线。

## 2. 安装所选浏览器扩展

- 对用户选中的每个浏览器，使用电脑操作工具打开 `edge://extensions` 或 `chrome://extensions`，开启「开发人员模式」（开发者模式），点击「加载已解压的扩展程序」（加载已解压的扩展），选择 `PROJECT\browser\extension`，将「一角：存当前页到随记」固定到工具栏。不要将浏览器扩展指向临时目录，更新或移动项目后需重新选择新位置。
- 浏览器扩展默认向系统的 `edgetodo://` 协议发送请求；若本次仅在做不改动主协议的隔离测试，请勿用扩展点击结果来代替 `edgetodo-test://` 隔离验证（因为系统仍会把 `edgetodo://` 交给主协议指向的版本）。确认主协议或测试环境备份方案就绪后，用普通网页点击工具栏图标，处理浏览器「打开 一角」确认弹窗（若首次点击仅授予权限，待权限生效后再点一次），核对网页标题和完整链接确实出现在目标 一角 的「随记」里，且重启应用后依然保留。多选浏览器时逐个验证（如果临时改过注册表，测试完成后立即恢复原始注册表）。
- 若无法操作扩展管理页、文件选择器或系统确认，继续飞书及其他可做步骤，主动提供逐步人工引导：说明打开浏览器扩展管理页、开启开发者模式、点击加载已解压的扩展、粘贴 `PROJECT\browser\extension` 实际路径并选择文件夹、固定图标并测试。不要更改企业策略或关闭系统安全保护。

## 3. 飞书同步（默认关闭，仅在用户选择开启后配置）

- **默认关闭原则**：未配置 `feishu-settings.json` 时，Windows 版「一角」默认完全关闭飞书同步，所有数据仅保存在本机。只有在用户主动选择开启飞书归档并同意授权时，才执行以下步骤。
- 检查 `lark-cli` 是否存在及其版本，读取本机可用的飞书认证、Base 和文档技能以及当前 CLI 的 help。找不到时根据飞书 CLI 官方说明安装；若无法自动安装，告诉用户缺少的工具、官方安装方式和下一步，继续能完成的部分。
- 不覆盖现有 CLI 配置。用户已有可用的飞书账号配置时可以复用；否则创建独立配置，引导用户通过飞书完成登录与授权。按单个最小权限 scope 申请创建多维表格、读取字段、读写记录、创建及读写文档权限；不要使用全业务域授权。不要索取或展示密钥和 token。
- **开启前务必提醒用户**：告知用户开启飞书同步后，程序会把本机已有待办、随记和网页链接写到自己的飞书表格中，且**专用飞书云文档会被程序整篇覆盖更新**；请勿在该专用云文档中手动存放其他非归档内容。
- 以已授权用户的身份创建专用多维表格（含三个文本字段「日期」「今日待办」「随记」）和一篇专用空白飞书云文档。读取真实返回获取 Base token、table ID、文档 ID 和资源直链，不要猜测标识，并在数据目录中记录已创建的资源标识以便核对复用。
- 在前述数据目录中原子写入 `feishu-settings.json`，包含 `table`、`document`、`profile`、`cliPath`、`accountID`，分别为数据表直链、文档直链、实际 CLI 配置名称、CLI 可执行文件路径和已授权用户 openId。凭据由 `lark-cli` 保管。只重启本次配置的应用实例使设置生效，不影响其他运行中的版本。
- 使用隔离测试数据和专用测试资源验证：带标题网页收藏（需保留完整网址）与多行随记的同步、断网情况下本机保存正常、恢复联网后可自动补同步到表格与文档。

## 4. 完成后告诉用户

简短报告：
1. 实际安装的浏览器扩展及验证结果；
2. 应用安装目录与**本地数据文件夹的完整绝对路径**（重点明确告知数据存在哪）；
3. 飞书同步状态（默认关闭，或已开启并列出专用表格和云文档链接）；
4. 任何未完成事项与可直接照做的下一步（不要声称未验证的功能成功）。
